## 1. 目的

SPEC §5（非機能: Tailwind でレスポンシブ・ダッシュボード初期表示2秒以内）と各ワイヤーフレーム（docs/wireframes/）が前提とする共通 app shell（左サイドナビ + 上部トップバー + コンテンツ領域）を `(protected)` 配下に新規実装する。あわせて WF 04-dashboard.html のデザイントークン（カラー/間隔/角丸）を全ページから利用可能な共通基盤として整備し、後続の LAP-015（保護ページのコンテンツ整合）・LAP-017（設定画面）の土台とする。本チケットは **shell + トークン基盤まで**で、各ページのコンテンツ整合（KPI/グリッド/テーブル）は LAP-015 に委譲する。

## 2. 現状

**現在のフロー:**
```

       └─ {children}
            ├─ (公開) /, /login, /invite/*, /password-reset/* … カード中央寄せを前提
```

- `(protected)/layout.tsx` は **存在しない**。app shell（サイドナビ・トップバー）は未実装。dashboard/page.tsx が簡易ナビ・ログイン中メール表示・`LogoutButton` をインラインで持つ。

- 認証情報源は `src/lib/auth-helpers.ts` の `getCurrentUser()`（`{id,email,isAdmin}` を返す server 関数）。ログアウトは `src/app/(protected)/logout-button.tsx`（インライン `"use server"` で `signOut({redirectTo:"/login"})`）。
- vitest は **node 環境**・`globals:true`・`src/**/*.test.ts` を対象（jsdom/RTL 未導入）。

## 3. 設計方針

### 3.0 判断点の決定（investigator の architect 判断点に対する確定）

| # | 論点 | 決定 |
|---|---|---|
| 1 | 保護ルートのみ全幅 shell 化 | **root layout.tsx から中央寄せラッパ `<div class="mx-auto max-w-screen-lg ...">` を撤去**し、`{children}` を裸で出力する。公開ページ（`/`・`/login` 等）は **元の中央寄せ見た目を自身で保持できる**（`page.tsx` は `flex ... items-center justify-center py-16`、`login/page.tsx` は `flex min-h-[80vh] ... justify-center`、ともに自前で中央寄せ済みで `max-w-screen-lg` ラッパに依存していない）。保護側は `(protected)/layout.tsx` が全幅フレックス shell を構成する。これにより公開ページ・保護ページの双方が後退しない。**代替案（root ラッパ維持＋(protected) で打ち消し）は採らない**（`max-w` を子で打ち消すのは脆く、二重ラップが残るため）。 |
| 2 | (protected)/layout.tsx の構成 | **server component**。`getCurrentUser()` を読み、未取得時は防御的に `/login` へ redirect（実認可は既存 require* と edge が担保するが、UI 上 email/admin を安全に扱うため）。レイアウトは「サイドナビ（admin 出し分け）+ トップバー（ユーザーチップ=email）+ `<main>`(children)」を構成。**client が必要な部分のみ子 client component に切り出す**（アクティブ判定の `usePathname`、モバイルドロワー開閉の `useState`）。 |
| 3 | デザイントークンの移植 | **globals.css の `@theme` ブロック**（Tailwind v4 のトークン定義機構）に WF 04 の `:root` 値を移植する。色は `--color-*` 命名、間隔は `--spacing-*`、角丸は `--radius-*` として定義し、Tailwind ユーティリティ（`bg-page`・`text-ink`・`rounded-card` 等）と CSS 変数 `var(--color-ink)` の双方から参照可能にする。後続 LAP-015/016/017 が同じトークンを利用する共通基盤とする。 |
| 4 | ナビ項目データ構造とアクティブ判定 | ナビ項目を **純データ配列**（`src/lib/nav.ts`）として定義（`{ key, label, href, adminOnly, matchMode }`）。アクティブ判定は **純関数** `isNavItemActive(currentPath, item)` に分離（`matchMode:"exact"` は完全一致＝`/dashboard`、`"prefix"` は前方一致＝`/dashboard/topics` 等）。**「`/dashboard` が全項目に前方一致する罠」は matchMode を項目ごとに持たせることで構造的に回避**（ダッシュボードのみ exact）。vitest（node）で単体テスト可能。 |
| 5 | トップバーのページタイトル受け渡し | **ナビ定義 + パス→タイトル導出の純関数 `pageTitleForPath(currentPath)`（`src/lib/nav.ts`）で解決**する。layout は静的にタイトルを知れないが、`usePathname()` を持つ client（トップバー）でパスからタイトルを導出できる。ナビ非掲載の詳細ルート（`/dashboard/topics/[id]/edit`・`/dashboard/topics/archived`・`/admin/invite` 等）は **最長前方一致**で親セクションのタイトルに丸める（WF の per-page 微細タイトルは LAP-015/017 で各 page が必要に応じ上書きする余地を残すが、本チケットでは導出のみで十分）。**per-page からの prop 受け渡しは採らない**（全 page 改修が必要になり scope が膨らむため。導出で WF 受け入れ条件「ページタイトル表示」を満たせる）。 |
| 6 | アカウントナビの暫定挙動 | **暫定で非活性（disabled）表示**とする。ラベルは表示しつつリンクを張らず（`<span>` でクリック不可・`aria-disabled` + 視覚的に dim）、「準備中」を示す。**非表示は採らない**（WF の 7 項目構成・ナビの完成像が見えなくなるため）。LAP-017 で `/dashboard/account`（実ルートは LAP-017 が確定）へのリンクに差し替える。ナビ定義に `disabled?: boolean` を持たせ、LAP-017 で `disabled` を外し `href` を設定するだけで有効化できるようにする。 |
| 7 | ログアウト | 既存 `logout-button.tsx` の `LogoutButton`（form + server action `signOut`）を **サイドナビ下部とモバイルメニューで再利用**する。WF は `<a>` 表現だが、実装は **form + server action**（GET リンクで副作用を起こさない）。ナビ項目の見た目に合わせるため `LogoutButton` の className を nav-item 風に調整する（既存の利用箇所＝dashboard インライン導線は本チケットで撤去するため影響は閉じる）。 |
| 8 | レスポンシブ | **Tailwind モバイルファースト**。既定（モバイル）は「上部バー（ハンバーガー + タイトル）+ コンテンツ + 下部タブ（主要4 + メニュー）」、`md:` 以上で「左サイドナビ固定 + トップバー + コンテンツ」。モバイルの「メニュー」ドロワー（管理/アカウント/ログアウト）開閉に **最小限の client component**（`MobileMenu`：`useState` で開閉、`usePathname` で閉じる）を用いる。サイドナビ本体は `hidden md:flex`、下部タブ/モバイル上部バーは `md:hidden`。 |
| 9 | テスト方針 | **純ロジックを `src/lib/nav.ts` に集約**し、`src/lib/nav.test.ts`（vitest/node）で単体テスト：ナビ項目定義の整合・`isNavItemActive`（exact/prefix・dashboard 罠）・`visibleNavItems(isAdmin)`（admin 出し分け）・`pageTitleForPath`（最長前方一致）。**コンポーネント描画テストは現環境（jsdom/RTL 未導入）では行わない**（環境追加は scope 外。`npm run build` + 型チェックで描画系の健全性を担保）。 |

### 3.1 採用する方針（まとめ）

- **トークン**: globals.css `@theme` に WF 04 トークンを一元定義（色/間隔/角丸/フォント変数の橋渡し）。共通基盤として全ページ参照可能に。
- **shell**: root から中央寄せラッパを撤去 → 公開ページは自前中央寄せで不変、保護ページは `(protected)/layout.tsx` が全幅 shell。
- **責務分離**: layout(server) はデータ取得（getCurrentUser）と静的構造。`usePathname`/開閉のみ client（`Sidenav` のアクティブ判定・`MobileMenu`）。
- **純ロジック外出し**: ナビ定義・アクティブ判定・admin 出し分け・タイトル導出を `src/lib/nav.ts` に集約し node 環境でテスト。

**代替案と却下理由:**
| 案 | 却下理由 |
|---|---|
| root ラッパ維持＋(protected) 側で `max-w` を打ち消す | 子で親の `max-w`/`mx-auto` を打ち消すのは脆く二重ラップが残る。公開/保護の責務が曖昧になる |
| ページタイトルを各 page から prop で渡す | 全保護 page の改修が必要で scope 肥大。パス→タイトル導出で受け入れ条件を満たせる |
| トークンを tailwind.config.ts の theme.extend に定義 | v4 は CSS-first。`@theme`（globals.css）が正。config 側は content glob 専用に留める方が一貫 |
| アカウントナビを非表示 | ナビ完成像が見えず、LAP-017 完了まで UX が不完全に見える。非活性の方が意図が伝わる |
| サイドナビ全体を client component 化 | サーバーで取得した user/isAdmin を渡せば描画はサーバーで足りる。client は `usePathname`/開閉に限定するのが軽量 |

## 4. 実装詳細

**ファイル構成（変更・追加）:**
```
src/
├── app/
│   ├── layout.tsx                         # 変更: 中央寄せラッパ <div> を撤去し {children} を裸出力
│   ├── globals.css                        # 変更: @theme に WF トークン（色/間隔/角丸）追加。body 背景を --color-page に
│   └── (protected)/
│       ├── layout.tsx                     # 新規: server component。app shell（Sidenav + Topbar + main）
│       ├── logout-button.tsx              # 変更: nav-item 風 className（サイドナビ/モバイルメニューで再利用）
│       └── dashboard/page.tsx             # 変更: インラインの簡易ナビ・LogoutButton・ログイン中メール表示を撤去（shell に集約。集計ロジックは不変）
├── components/
│   └── shell/
│       ├── sidenav.tsx                    # 新規(client): PC 左サイドナビ。usePathname でアクティブ判定。props で user/isAdmin/navItems を受領
│       ├── topbar.tsx                     # 新規(client): トップバー。usePathname で pageTitleForPath、user-chip(email)
│       ├── mobile-menu.tsx               # 新規(client): モバイル上部バー(ハンバーガー) + ドロワー(管理/アカウント/ログアウト) + 下部タブ。useState 開閉
│       └── brand-logo.tsx                # 新規: ブランド svg(グレースケール版) + "Lapsy"(Fredoka)。server で可
└── lib/
    ├── nav.ts                             # 新規: ナビ定義配列 + 純関数(isNavItemActive / visibleNavItems / pageTitleForPath)
    └── nav.test.ts                        # 新規(vitest/node): nav.ts の単体テスト
```

**主要なインターフェース（`src/lib/nav.ts`）:**
```typescript
export type NavMatchMode = "exact" | "prefix";

export type NavItem = {
  key: string;            // 安定キー（react key / テスト用）
  label: string;          // 表示ラベル（例: "ダッシュボード"）
  href: string;           // 遷移先（disabled の項目は "#" 等のダミーでも可だがリンクは張らない）
  matchMode: NavMatchMode;// アクティブ判定方式
  adminOnly?: boolean;    // admin のみ表示（UI 出し分け。実認可は require* が担保）
  disabled?: boolean;     // 暫定非活性（LAP-017 までのアカウント）
  // アイコンは実装側で key→アイコンの対応表を持つ（nav.ts は純データに保つ）
};

// 主要ナビ（上段）。順序は WF に準拠: ダッシュボード/タイマー/トピック/プリセット/管理
export const PRIMARY_NAV: readonly NavItem[];
// 下段（nav-sep の下）: アカウント(disabled)/ログアウト(ログアウトは別途 form なので nav とは別管理可)
export const SECONDARY_NAV: readonly NavItem[];

// 実ルート対応（investigator 確定）:
//  ダッシュボード /dashboard           matchMode:"exact"
//  タイマー       /dashboard/sessions  matchMode:"prefix"
//  トピック       /dashboard/topics    matchMode:"prefix"
//  プリセット     /dashboard/presets   matchMode:"prefix"
//  管理(Admin)    /admin/users         matchMode:"prefix" (※ /admin/invite も含めるため /admin 前方一致でも可。href は /admin/users) adminOnly:true
//  アカウント     (未実装)             disabled:true（LAP-017 で href 設定）

// 現在パスが項目にマッチするか（exact: 完全一致, prefix: currentPath===href || currentPath.startsWith(href+"/")）
export function isNavItemActive(currentPath: string, item: NavItem): boolean;

// admin 出し分け後の表示項目（adminOnly は isAdmin=true のときのみ）
export function visibleNavItems(items: readonly NavItem[], isAdmin: boolean): NavItem[];

// パス→ページタイトル（最長前方一致。未掲載の詳細ルートは親セクションのタイトルへ丸める。
// 既定フォールバックは "Lapsy" もしくは空ではなく最寄りセクション名）
export function pageTitleForPath(currentPath: string): string;
```

`isNavItemActive` の prefix 実装は **`startsWith(href + "/")` または完全一致**とし、`/dashboard` と `/dashboard/topics` のような兄弟接頭辞の誤判定を防ぐ（`/dashboard` は exact なので `/dashboard/topics` 上でアクティブにならない＝罠回避）。

**コンポーネント責務:**
- `(protected)/layout.tsx`（server）: `const user = await getCurrentUser(); if (!user) redirect("/login");` → `visibleNavItems(...)` を渡さず **生の定義配列 + isAdmin を子に渡す**か、サーバー側で `visibleNavItems` 済み配列を渡す（後者を採用＝client へ admin 判定を漏らさない）。`<div class="flex min-h-screen">` で Sidenav + main(Topbar + content)。
- `Sidenav`（client）: `usePathname()` でアクティブ class。`hidden md:flex`。ブランド(BrandLogo) + 主要ナビ + `nav-fill`(flex-1) + セパレータ + アカウント(非活性) + `LogoutButton`。
- `Topbar`（client）: `usePathname()` → `pageTitleForPath`。`h2`(Fredoka 16px) + spacer + user-chip(email + avatar 円)。`hidden md:flex`。email は **props（server から）で受領**（client で auth を読まない）。
- `MobileMenu`（client）: `md:hidden`。上部バー(ハンバーガー + 中央タイトル) + 下部タブ(ダッシュ/タイマー/トピック/プリセット/メニュー)。「メニュー」タップで `useState` ドロワー展開（管理[admin のみ]/アカウント[非活性]/ログアウト）。`usePathname` 変化でドロワーを閉じる。
- `BrandLogo`（server 可）: WF のグレースケール svg（04-dashboard.html の nav-brand svg、`#DADADA`/`#FFFFFF` 系）+ Fredoka "Lapsy"。**`src/app/icon.svg`（彩色版）とは別**。グレースケール shell に合わせ WF の svg を採用する。

**globals.css `@theme` トークン（移植元: WF 04 `:root`）:**
```css
@import "tailwindcss";

@theme {
  /* colors（WF グレースケール） */
  --color-page: #E9E9E9;  --color-panel: #F3F3F3;  --color-card: #FFFFFF;  --color-fill: #F4F4F4;
  --color-line: #CFCFCF;  --color-line-2: #B6B6B6; --color-line-strong: #9A9A9A;
  --color-ink: #454545;   --color-ink-dim: #7E7E7E; --color-placeholder: #B2B2B2;
  --color-btn: #6F6F6F;   --color-btn-ink: #FFFFFF; --color-marker: #5C5C5C; --color-error: #7A7A7A;
  /* radius */
  --radius-card: 16px;    --radius-ctl: 12px;
  /* spacing は WF の s1..s5(8/12/16/24/32) を既存 Tailwind の spacing スケールに概ね対応させる
     （8=2, 12=3, 16=4, 24=6, 32=8）。固有名が必要なら --spacing-s1.. を追加で定義 */
}

body { background: var(--color-page); color: var(--color-ink); }
```
- 既存 `--background/--foreground` は撤去または `--color-page/--color-ink` へ寄せる（公開ページが直接参照していないか implementer が確認。login/page・home は Tailwind の gray-* と white を直接使用＝グレースケールトークンとは独立で後退しない。本チケットでは公開ページの色は変更しない）。
- フォントは root layout の `--font-fredoka`/`--font-noto-sans-jp`（既存）を利用。見出し/ブランドに Fredoka、本文に Noto Sans JP。

**処理フロー（保護ページ描画）:**
```
1. リクエスト → edge(middleware/auth.config) が /dashboard|/admin をログイン必須に保護（既存・不変）
2. (protected)/layout.tsx(server): getCurrentUser() → null なら /login へ redirect（防御）
3. layout が visibleNavItems(PRIMARY_NAV, user.isAdmin) を算出し、Sidenav/Topbar/MobileMenu に
   navItems・email を props で渡す（admin 判定は server で消費済み）
4. Sidenav/Topbar(client) が usePathname() でアクティブ class とページタイトルを決定
5. <main>(children) に各 page の内容（dashboard 等）が描画される。各 page は require*() を従来どおり実行（不変）
```

## 8. ロールバック戦略

shell はプレゼンテーション層の追加が中心で、認証・データに副作用がないため `git revert` で安全に戻せる。

```bash
# 1. 問題コミットを特定
git log --oneline
# 2. revert（コミット自動生成）
git revert {コミットハッシュ}
# 3. メッセージにチケットIDを付与
#    例: [LAP-014][REVERT] 共通 app shell の実装を取り消し
```
- 部分的に戻す場合: `src/app/layout.tsx` の中央寄せラッパのみ復元すれば公開ページ側の見た目は即時に旧状態へ戻せる（保護ページは shell が無くなり各 page の従来描画に戻る）。
- `(protected)/layout.tsx` を削除すると shell は無効化され、各保護 page は従来どおり単体描画される（認証は不変なので機能は維持）。
