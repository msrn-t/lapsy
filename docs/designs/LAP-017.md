## 1. 目的

ワイヤーフレームに存在するが未実装の 2 種のページを新規実装する。

- **設定ページ `/dashboard/account`**（WF 11-settings）: ログイン中ユーザーの ① 表示名編集 ② パスワード変更（現在PW照合 + 新PW + 確認 + 強度メーター） ③ 全端末からのログアウト（`sessionVersion` 一括失効・SPEC §6）。app shell（LAP-014）内に配置し、`requireUserId` で保護する。
- **エラーページ**（WF 12-errors）: `src/app/not-found.tsx`（404）と `src/app/error.tsx`（500/ランタイム・client・`{error,reset}`）の 2 点。機密/スタックトレースをユーザー向けに露出しない。

人間判断 U1-U4（チケットログ 2026-06-22 16:04）を確定スコープとして従う。エラーページは 401/403/429 専用着地を作らず既存 redirect を維持する（U2）。設定 URL は `/dashboard/account`（既存 middleware の `/dashboard` 保護で自動カバー・`auth.config.ts` 不変・U3）。全端末ログアウト後は `signOut`→`/login`（U4）。

## 3. 設計方針

### 3.0 採用する方針（まとめ）

1. **設定ページは server component + 1 client フォーム**: `page.tsx`（server・`requireUserId` で保護・Prisma で `name` を直読・3 カード描画・3 つの server action を定義）と、パスワード変更カードのみ `_password-form.tsx`（client・`useFormStatus` + 強度メーター + 確認 + 表示トグル・`invite/[token]/_form.tsx` と同型）に分離する。表示名カード・全端末ログアウトカードは状態を持たない素の `<form action={...}>` で十分なので client 化しない（早すぎる抽象化を避ける）。
2. **結果通知は既存の `?result=` + バナー方式**（presets と統一）: 各 server action は処理後 `redirect("/dashboard/account?result=KIND")` に集約し、`page.tsx` が `searchParams.result` を `ResultBanner` で表示する。WF note の「トーストで通知」はトースト基盤が無いため、既存パターンと一貫するバナーで代替する（新規 UI 基盤を持ち込まない）。
3. **`name` はセッション非伝播のまま Prisma 直読**: 設定ページは表示時に `prisma.user.findUnique({ where:{id:userId}, select:{name:true} })` で現在値を読む。更新 action は `prisma.user.update({ where:{id:userId}, data:{name} })` + `revalidatePath("/dashboard/account")`。**JWT へ `name` を載せない**（スコープ拡大・investigator Risk②）。Topbar の表示は本チケットでは変更しない（email 表示のまま）。
4. **パスワード変更の現在PW照合 + 8文字検証はサーバーが最終防壁**: action 内で `prisma.user.findUnique` → `verifyPassword(current, hash)` → `validateNewPassword(next)` → `hashPassword(next)` → `prisma.user.update`。強度メーター・確認一致は**クライアント表示専用**（`scorePasswordStrength`/`passwordsMatch`・ゲートにしない）。確認値 `passwordConfirm` は**サーバーで読まない**（LAP-016 と同じ契約）。
5. **全端末ログアウトは `bumpSessionVersion`→`signOut`→`/login`**: 自己 JWT も失効するため、action 内で `bumpSessionVersion(userId)` の後 `signOut({ redirectTo:"/login" })` する（U4）。`signOut` は `NEXT_REDIRECT` を throw するため try/catch で囲わない（presets/login と同様、redirect は素通しさせる）。
6. **nav.ts は最小差分で activate**: `SECONDARY_NAV.account` の `disabled:true` を除去・`href:"#"`→`"/dashboard/account"`・`matchMode` は `"exact"` のまま（`/dashboard/account` 配下に子ルートが無いため）。`TITLE_TABLE` に `{ prefix:"/dashboard/account", title:"アカウント設定" }` を追加。**`/dashboard/sessions`〜`/dashboard` の既存エントリ順は壊さない**（`pageTitleForPath` は最長前方一致なので `/dashboard/account` は `/dashboard` より長く正しく解決される。配列順は判定に影響しないが、可読性のため `/dashboard` 直前に置く）。他の nav 項目・既存タイトル文字列は不変。
7. **nav.test.ts を新状態へ同期更新**: `account.disabled===true` の検証（L45-47）を「`disabled` を持たず href が実ルート」へ書き換える。`isNavItemActive("/dashboard/account", account)===false`（L118・disabled 前提）を、**activate 後の真値（`true`）**へ更新する。タイトル検証に `pageTitleForPath("/dashboard/account")==="アカウント設定"` を追加。**既存の他テスト（PRIMARY_NAV 順序・admin・タイトル他）は不変**。
8. **エラーページはルート直下に配置（shell 外・中央寄せカード）**: `src/app/not-found.tsx`・`src/app/error.tsx` をルート `app/` 直下に置く。理由 — (a) WF 12-errors はロゴ + コード + 説明 + 復帰ボタン 1 つの**中央寄せ・shell 無し**フルスクリーンで、サイドナビ/トップバーを出さない構成。(b) Next.js の規約上、ルート直下の `not-found.tsx` は全 unmatched パス（公開/保護問わず）に効き、`error.tsx` はルートセグメントのエラー境界になる。`(protected)` 配下に置くと公開ページのエラーを拾えない。(c) `(protected)/layout.tsx` を通らないため shell 非依存で WF と一致する。**root `layout.tsx` の `{children}` 裸出力**（中央寄せラッパ撤去済）と整合し、各ファイルが自前で `min-h-screen flex items-center justify-center` する。
9. **`error.tsx` は機密非露出**: `"use client"` で `{ error, reset }` を受け取るが、画面には**固定文言のみ**を出す。`error.message`/stack は描画しない。`error.digest` は任意で小さく表示してよい（サポート照合用・機密でない相関ID）。`useEffect` で `console.error(error)` してサーバー/クライアントログに残す（ユーザー画面には出さない）。

### 3.2 設定 server action の入力契約と結果コード

3 つの action は `page.tsx` 内に `"use server"` で定義し、すべて `requireUserId()` で認可。結果は `redirect("/dashboard/account?result=KIND")` に集約する（presets 方式）。

| action | 入力（formData） | 認可 / Prisma | 成功 KIND | 失敗 KIND |
|---|---|---|---|---|
| `updateDisplayName` | `name`（任意・空可） | `requireUserId` → `validateDisplayName(name)` → `prisma.user.update({where:{id:userId},data:{name}})` → `revalidatePath` | `name_updated` | `name_too_long` |
| `changePassword` | `currentPassword` / `password` / （`passwordConfirm` は**読まない**） | `requireUserId` → `findUnique({where:{id}})` → `verifyPassword(current, hash)` → `validateNewPassword(next)` → `hashPassword` → `update({where:{id:userId},data:{passwordHash}})` → `revalidatePath` | `password_changed` | `current_password_wrong` / `weak_password` |
| `logoutAllDevices` | （なし） | `requireUserId` → `bumpSessionVersion(userId)` → `signOut({redirectTo:"/login"})` | （/login へ離脱・KIND 不要） | （なし） |

**結果コード（`ResultKind`）と文言（`ResultBanner`）:**

| KIND | 種別 | 文言 |
|---|---|---|
| `name_updated` | 成功 | 表示名を更新しました。 |
| `password_changed` | 成功 | パスワードを変更しました。 |
| `name_too_long` | 失敗 | 表示名が長すぎます（50文字以内）。 |
| `current_password_wrong` | 失敗 | 現在のパスワードが正しくありません。 |
| `weak_password` | 失敗 | 新しいパスワードは8文字以上で設定してください。 |

> `current_password_wrong` は WF note「現在パスワード誤り」の状態に対応。表示はバナー（フォーム上部）で行い、加えてパスワードカードでは現在PWフィールドに `.input.error` を付けてよい（クライアントは初期状態を持たないため、`?result=current_password_wrong` をフォームへ渡してエラー枠/メッセージを出す。`invite/_form.tsx` の `initialError` と同型）。
> パスワード変更後に**自己セッションを失効させるか**は WF note が「運用方針による」とした未確定事項だが、U4 は「全端末ログアウト」専用と読めるため、**本チケットではパスワード変更で `bumpSessionVersion` しない**（変更後もログイン継続）。失効が要件なら別チケット（Open Questions なし・既定挙動として確定）。

### 3.3 表示名バリデーション純関数（`validateDisplayName`・新設）

表示名は `User.name`（`String?`・任意）。WF は「任意項目・即時保存」。SPEC に最大長の定義は無いため、architect 裁量で**前後 trim + 上限 50 文字**を定める（一覧表示・DoS 抑止の実用範囲）。空文字は許容し `null` 化する（任意項目のため未設定に戻せる）。

```ts
// src/lib/account.ts に新設（DB/bcrypt 非依存・node テスト対象）
export const MAX_DISPLAY_NAME_LENGTH = 50;

export type DisplayNameResult =
  | { ok: true; value: string | null }
  | { ok: false; error: "name_too_long" };

/** 表示名を正規化・検証する純関数。trim 後、空なら null（未設定）、上限超過は失敗。 */
export function validateDisplayName(raw: string): DisplayNameResult {
  const trimmed = raw.trim();
  if (trimmed.length === 0) return { ok: true, value: null };
  if (trimmed.length > MAX_DISPLAY_NAME_LENGTH) {
    return { ok: false, error: "name_too_long" };
  }
  return { ok: true, value: trimmed };
}
```

**強度メーター塗り幅（クライアント表示マップ・`invite/_form.tsx` と同一）:**
| strength | 塗り幅 | クラス |
|---|---|---|
| weak | 33% | `w-1/3` |
| medium | 66% | `w-2/3` |
| strong | 100% | `w-full` |

強度メーターは**ゲートにしない**: weak でもサーバーは現在PW一致 + 新PW 8 文字を満たせば受理する。

**代替案と却下理由:**
| 案 | 却下理由 |
|---|---|
| 表示名/PW変更 action を専用 `actions.ts` ファイルに切り出す | presets 等の既存 protected ページは `page.tsx` 内 `"use server"` で完結している。設定ページも同型に揃え、ファイルを増やさない |
| 結果通知をトースト UI で実装（WF note 準拠） | トースト基盤が未導入。新規 UI 基盤の持ち込みは scope 拡大。既存 `?result=` バナー（presets）で一貫させる |
| `name` を JWT に載せて Topbar に表示名を出す | investigator Risk②・JWT スコープ拡大。設定ページは Prisma 直読で足り、Topbar 変更は本チケット外 |
| パスワード変更時に自端末も即失効（再ログイン強制） | WF note が「運用方針による」。U4 は全端末ログアウト専用。変更後ログイン継続を既定とし、失効は別チケット |
| 401/403/429 専用エラーページを作る | U2 で既定 redirect 維持と確定（middleware→/login・requireAdmin→/dashboard）。404+500 の 2 点のみ |
| `error.tsx` に `error.message` を表示 | 機密/スタック露出（受け入れ条件・Risk）。固定文言 + 任意 `digest` のみ |
| エラーページを `(protected)` 配下に置く | 公開ページのエラー/404 を拾えず、shell が被さって WF と不一致。ルート直下が規約上正しい |

### 4-3. 設定ページ `src/app/(protected)/dashboard/account/page.tsx`（server）

**WF 構造（11-settings PC）**: page-h「アカウント設定」→ ① 表示名カード（input + 「保存」ボタン横並び）→ ② パスワード変更カード（現在/新規 + 強度メーター/確認 + 「パスワードを更新」）→ ③ セッションカード（説明 + 「全端末からログアウト」ghost ボタン）。各カード `max-w-[480px]`・縦に `gap`。モバイルは縦積み・全幅ボタン（Tailwind は同一マークアップで自然に縦積み・ボタンに `w-full sm:w-auto` 等は不要、`.card` を縦 stack に）。

**処理フロー（描画）:**
```
1. const userId = await requireUserId();
2. const { result } = await searchParams;   // ?result=KIND
3. const user = await prisma.user.findUnique({ where:{ id:userId }, select:{ name:true } });
4. <main> 内に page-h + (result があれば ResultBanner) + 3 カードを描画。

   - ② パスワード: <PasswordChangeForm action={changePassword} initialError={result が PW 系なら result} />（client）。
   - ③ セッション: <form action={logoutAllDevices}> に説明 + ghost ボタン（type=submit）。
```

**server action（`"use server"`・page.tsx 末尾に定義）:**
```ts
// 表示名（§3.2）
async function updateDisplayName(formData: FormData) {
  "use server";
  const userId = await requireUserId();
  const back = (k: ResultKind) => redirect(`/dashboard/account?result=${k}`);
  const r = validateDisplayName(String(formData.get("name") ?? ""));
  if (!r.ok) return back(r.error);          // name_too_long
  await prisma.user.update({ where:{ id:userId }, data:{ name:r.value } });
  revalidatePath("/dashboard/account");
  back("name_updated");
}

// パスワード変更（§3.2・確認値 passwordConfirm は読まない）
async function changePassword(formData: FormData) {
  "use server";
  const userId = await requireUserId();
  const back = (k: ResultKind) => redirect(`/dashboard/account?result=${k}`);
  const current = String(formData.get("currentPassword") ?? "");
  const next = String(formData.get("password") ?? "");
  const user = await prisma.user.findUnique({ where:{ id:userId }, select:{ passwordHash:true } });
  if (!user) redirect("/login");            // セッション有効でも防御的に
  const ok = await verifyPassword(current, user.passwordHash);
  if (!ok) return back("current_password_wrong");
  const v = validateNewPassword(next);
  if (!v.ok) return back("weak_password");
  const passwordHash = await hashPassword(next);
  await prisma.user.update({ where:{ id:userId }, data:{ passwordHash } });
  revalidatePath("/dashboard/account");
  back("password_changed");
}

// 全端末ログアウト（U4）
async function logoutAllDevices() {
  "use server";
  const userId = await requireUserId();
  await bumpSessionVersion(userId);          // 既存セッションを一括失効（§6）
  await signOut({ redirectTo: "/login" });   // 自己 JWT も失効 → 再ログインへ
}
```
- import: `requireUserId`（auth-helpers）、`prisma`、`verifyPassword`/`hashPassword`（password）、`validateNewPassword`（password-reset）、`validateDisplayName`（account）、`bumpSessionVersion`（auth-revocation）、`signOut`（@/auth）、`revalidatePath`（next/cache）、`redirect`（next/navigation）。
- `ResultKind` 判定・`ResultBanner` は presets と同型でこの page 内にローカル定義。

### 4-4. パスワード変更フォーム `_password-form.tsx`（client）

`invite/[token]/_form.tsx` を**手本にした同型コンポーネント**。差分は「現在のパスワード」フィールドが先頭に増える点と、`initialError` がパスワード変更系の result（`current_password_wrong`/`weak_password`）である点。

- props: `action: (formData: FormData) => Promise<void>`、`initialError?: string`。
- state: `pw`/`confirm`/`showCurrent`/`showPw`/`showConfirm`。`strength = scorePasswordStrength(pw)`、`mismatch = confirm.length>0 && !passwordsMatch(pw, confirm)`。
- フィールド:
  1. 現在のパスワード `name="currentPassword"` `type={showCurrent?"text":"password"}` `required` `autoComplete="current-password"` + 表示トグル。`initialError==="current_password_wrong"` のとき `.input.error` + 直下に `.err-msg`「現在のパスワードが正しくありません」。
  2. 新しいパスワード `name="password"` `required` `minLength={8}` `autoComplete="new-password"` + 表示トグル + 強度メーター（§3.3）+ help「8文字以上 / 強度は目安です」。
  3. 新しいパスワード（確認）`name="passwordConfirm"`（**サーバー無視**）+ 表示トグル + `mismatch` 時 `.input.error` + 直下 `.err-msg`「パスワードが一致しません」。
- 送信: `SubmitButton`（`useFormStatus`・pending 中「更新中…」・通常「パスワードを更新」）。`disabled={pending || mismatch}`。
- `initialError`（PW系のみ）は WF `.form-error` 相当でフォーム上部に出してよい（`current_password_wrong`/`weak_password` の文言は §3.2）。`name_updated`/`name_too_long`/`name`系 result はパスワードフォームには渡さない（表示名カード・ページ上部のバナーで扱う）。
- `<fieldset disabled={pending} className="contents">` で pending 中の入力ロックも踏襲。
- **client/server 分離の不変条件**: server action は親の `page.tsx` から prop 渡し（`invite/page.tsx`→`_form.tsx` と同型）。`passwordConfirm` は SSR/JS 無効でも送られるが**サーバーは読まない**（8文字 + 現在PW照合が最終防壁）。

### 4-6. エラーページ `src/app/error.tsx`（500/ランタイム・client）

Next.js のエラー境界規約: ルート `app/error.tsx` は `"use client"` 必須で `{ error: Error & { digest?: string }, reset: () => void }` を受け取る。
```tsx
"use client";
import { useEffect } from "react";
import { BrandIcon } from "@/components/brand-icon";

export default function Error({ error, reset }:
  { error: Error & { digest?: string }; reset: () => void }) {
  useEffect(() => {
    // サーバー/クライアントログにのみ残す。画面には出さない（機密非露出）。
    console.error(error);
  }, [error]);

  return (
    <main className="flex min-h-screen flex-col items-center justify-center bg-page p-6">
      <div className="w-full max-w-[420px] rounded-card border border-line bg-card px-6 py-8 text-center">
        <BrandIcon size={52} />
        <p className="...text-5xl font-semibold text-ink">500</p>
        <h2 className="...text-base font-semibold text-ink">問題が発生しました</h2>
        <p className="text-xs leading-relaxed text-ink-dim">
          サーバー側でエラーが発生しました。時間をおいて再度お試しください。
        </p>
        <button onClick={() => reset()} className="...btn.sm">再読み込み</button>
        {error.digest ? (
          <p className="mt-3 text-[10px] text-ink-dim">エラーID: {error.digest}</p>
        ) : null}
      </div>
    </main>
  );
}
```
- **機密非露出**: `error.message` / stack を**描画しない**。`error.digest`（Next が付与する相関ハッシュ・機密でない）のみ任意表示。`console.error` はログ限定。
- 復帰アクション = `reset()`（WF「再読み込み」）。WF どおり 1 アクション。
- `BrandIcon` をルートエラーで使うのは安全（依存が軽い純 SVG）。
